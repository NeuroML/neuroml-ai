## Objective

Two tracks: complete the RAG E2E store pipeline walkthrough
(openworm-papers + WormAtlas), and rework conversation memory into a

and tool reorganization planning).

## Completed

### E2E store pipeline (openworm-papers + WormAtlas)

- Re-chunked both corpora under the updated extraction code; templates
  now written to `.klea-cache/`, curated `metadata-map.json` files moved
  alongside.
- Initial manifest-based stores: wormatlas (26 files, 1472 chunks) and
  celegans (31 files, 2775 chunks); deterministic chunk IDs
  (`file_name:idx`) and chroma/BM25 counts consistent.
- Manifest-based incremental store validated: adding two PDFs embedded
  only the new files (31 -> 33, no duplicates); proved
  location-independent (chroma/BM25 moved out of the source dir, no
  `--force` needed).
- Store-directory exclusion: `_find_files` skips the vector store dir
  (configured `store_dir` or any dir containing `chroma.sqlite3`);
  `_store_dir` is scheme-generic (local folder for filesystem-backed
  URIs, `None` for remote schemes).
- Reconstructed the openworm-papers metadata map after an accidental
  deletion (a few files left for manual re-verification).

### Conversation memory rework

- Agent/RAG parity: the agent's guard model is now `modifiable=False`,
  `_setup_models` is marked `@override`, and `SummariseMemoryNode` is
  wired into the agent graph.
- `get_last_n_conversations` returns the ordered interleaved
  `BaseMessage` objects; new `get_recent_messages` returns a
  character-bounded tail (keeps >= 1); `add_memory_to_prompt` is now
  summary-only.
- Recent history is injected as real message objects between the system
  and human prompts: `_get_system_prompt` returns a `("system", text)`
  list plus history when memory is on, and `_create_prompt_template`
  accepts both forms. `num_history_messages` -> `num_history_chars`
  (10k chars).
- `SummariseMemoryNode` triggers on accumulated characters and only
  compresses history older than the verbatim window
  (`summarised_till = window_start`), so the summary and the verbatim
  window never overlap.
- RAG overrides (`classify_question`, `generate_retrieval_query`)
  updated for the list contract; unit tests added. Utils suite: 477
  tests, `ty` no new diagnostics, pre-commit clean.
- CHANGELOG: resolved a leftover merge conflict from the `development`
  merge (both sides were distinct additions; kept both).
- Tool inventory + reorganization plan: nml-mcp ships a duplicate
  `list_files` and testing-only echo tools; `testing` tag to be replaced
  with meaningful categories; the sandbox belongs in `klea_utils` (it
  predates the split into utils).
