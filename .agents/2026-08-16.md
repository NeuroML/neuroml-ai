## Session 1: RAG E2E store pipeline + conversation memory rework

### Objective

Complete the RAG E2E store pipeline walkthrough (openworm-papers + WormAtlas)
and rework conversation memory into a character-bounded, opencode-style context
budget, with agent/RAG parity and tool reorganization planning.

### Completed

- Re-chunked both corpora under the updated extraction code; templates live in
  `.klea-cache/`, curated `metadata-map.json` files alongside. Initial
  manifest-based stores: wormatlas (26 files, 1472 chunks) and celegans
  (31 files, 2775 chunks) with deterministic chunk IDs (`file_name:idx`).
- Manifest-based incremental store validated: adding two PDFs embedded only the
  new files (31 -> 33, no duplicates) and was location-independent.
- Store-directory exclusion in `_find_files`; `_store_dir` is scheme-generic.
- Agent/RAG parity: guard model `modifiable=False`, `_setup_models` marked
  `@override`, `SummariseMemoryNode` wired into the agent graph.
- Character-bounded history (`num_history_chars`, 10k): `get_recent_messages`,
  summary-only `add_memory_to_prompt`, real message objects injected between
  system and human prompts; `SummariseMemoryNode` never overlaps the verbatim
  window (`summarised_till = window_start`).
- RAG overrides updated for the list contract; unit tests added; CHANGELOG
  merge conflict resolved; tool inventory + reorganization plan written.

### Errors and Lessons

- The curated openworm-papers `metadata-map.json` was accidentally deleted;
  reconstructed from session context (a few values left for manual
  confirmation).
- `store --force` used to duplicate chunks (fresh UUIDs on re-add); the manifest
  model with deterministic IDs fixes this and `--force` now drops + rebuilds.
- Reverted the over-broad `*smoke.pkl` gitignore to the precise `smoke.pkl`.

### Open Questions

- Metadata-filter E2E should confirm the filter DSL handles string years.

## Session 2 (2026-08-16-1712): MCP tool permission layer + tool consolidation

### Objective

Add a permission layer for MCP tool calls, then consolidate the tool
picking/calling nodes shared by `klea_agent` and `klea_rag`.

### Completed

- Declarative path-permission metadata: `ToolInfo.checkpaths` lists path
  arguments; `register_tools` folds it into the tool `meta` (reaches clients on
  the MCP Tool `_meta`).
- Client-side `dispatch_tool_calls` gate checks declared paths against the cwd
  before dispatch and returns a non-halting error on denial (never invoking the
  server); in-tool `check_path_access` retained as a second layer.
- Declared `checkpaths` on bundled `list_files`/`read_file` and
  `neuroml_mcp.list_files`; added a `read_file` wrapper to the agent's bundled
  server.
- Standardised tool state on RAG's naming (`tool_calls`/`tool_results`);
  `ToolCallSchema`/`ToolCallsSchema` moved to `klea_utils.mcp.schemas`.
- Single shared `ToolsPicker` and `ToolsCallerNode` serve both apps (a
  `post_dispatch` callback carries the agent's per-plan-step update); the four
  app-side picker/caller node files were deleted.
- Node execution contract (`_pre_exec`, `_pre_exec_stream`, `_post_exec_stream`,
  `_get_info`/`_get_debug`/`_get_status`) moved up into
  `AbstractLangGraphNode`; `_get_usage` stayed in `AbstractLLMNode`.
- Tests for the permission helper, dispatch gate, and both shared nodes;
  devdocs updated. All suites green; `ty` at 29 pre-existing diagnostics.

### Errors and Lessons

- `ChatPromptTemplate.invoke` ignores extra variables, so one
  `ToolsPicker._get_prompt_variables` superset serves both apps (verified
  empirically).
- fastmcp's `call_tool` signature is too complex for a structural protocol; the
  dispatch client is typed `Any` and tested with a fake.

### Open Questions

- Interactive allow/deny/ask approval loop (opencode-style) still needs
  architecture design; the path gate ships first.

## Session 3 (2026-08-16-1730): NiceGUI inspector as a tab

### Objective

Move the NiceGUI inspector from a modal dialog (opened by an info button in the
status pane) to a dedicated "inspect" tab in the central pane, and fix the chat
layout + notification dismissal.

### Completed

- Central pane is now tabbed: "chat" + "inspect". Chat input + scroll area live
  in the chat tab; inspector entries render in the inspect tab.
- Removed the inspector info button from the right-drawer status pane
  (settings/model-config button kept).
- The inspect tab is always enabled. During a stream, inspector entries are
  buffered locally and only committed on completion, so the tab keeps showing
  the previous query's data until the new one finishes (no clear-at-start).
- Switching/deleting a chat resets the center pane to the chat tab and
  re-renders the inspector for the new chat.
- Pinned the chat input + disclaimer to the bottom: Quasar's hidden `.q-panel`
  wrapper (between `.q-tab-panels` and `.q-tab-panel`) was not flex-filling, so
  the panel stayed content-height. Fixed with scoped CSS
  (`.center-tab-panels > .q-panel { flex: 1; min-height: 0; display: flex;
  flex-direction: column; }`) plus inline flex styles on the tab panels;
  verified with live DOM/layout dumps via headless Chrome.
- Error notifications now use `close_button=True` (10s timeout) so they dismiss
  on click.
- Committed: `0a66dc1 feat(nicegui): move inspect to tab instead of button`.

### Errors and Lessons

- Two speculative CSS fixes for the layout bug were wrong; the real cause (the
  non-growing `.q-panel` wrapper) was only found by dumping the live rendered
  DOM. Empirical DOM inspection beat CSS theorising.
- Global `.q-tab-panel` CSS leaks into the model-config dialog's tab panels;
  scoped the rule to a `.center-tab-panels` class instead.

### Notes

- Confirmed there is still no write/patch file tool; only read-only file tools
  exist (`write_file`/`search_files`/`run_command` remain pending).
