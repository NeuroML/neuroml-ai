### Store pipeline re-run (both corpora)

- Re-chunked both corpora under the updated extraction code (keyword
  regex, title fallback, DOI fallback); templates now written to
  `.klea-cache/` (new location).  Curated `metadata-map.json` files

  1472 chunks) and celegans (31 files, 2775 chunks).  Manifests,
  deterministic chunk IDs (`file_name:idx`), and chroma/BM25 counts all
  consistent.

### Manifest-based incremental store validated

- Added two new PDFs (Albertson 1976, Atanas 2023) to openworm-papers
  and ran an **incremental** update: only the new files were embedded,
  the 31 existing files were skipped, no duplicates.  Manifest grew 31
  -> 33 files; chroma/BM25 grew by exactly the new chunks.
- **Proved the store is location-independent**: moved the chroma folder
  (and BM25 pickle) from inside the source dir to `tmp/stores/`, and the
  incremental update still worked with no `--force` -- the manifest in
  `.klea-cache/` is the source of truth, not the store path.
- Reconstructed the openworm-papers metadata map from context after the
  curated copy was accidentally deleted (bibliographic fixes, url
  stripping); a few files left for manual re-verification.

### Store-directory exclusion from ingestion

- `_find_files` now skips the vector store directory: both a configured
  `store_dir` and any directory containing a `chroma.sqlite3` inside the
  source dir.  Prevents nested stores from being scanned (and silences
  "skipping unsupported file" warnings).
- `_store_dir` is scheme-generic: returns a local folder for any
  filesystem-backed store URI and `None` for remote schemes (http /
  postgres URLs), so future local backends are covered without a
  per-scheme list.
