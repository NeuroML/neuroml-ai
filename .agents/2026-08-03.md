## Objective

Character-count logging for LLM invocations, per-vector-store retrieval settings, and a standard root-logger + file-logging refactor.

## Completed

### 1. LLM character-count logging
- Added `chars_sent` / `chars_received` DEBUG logging to the `AbstractLLMNode.execute()` template (`utils_pkg/klea_utils/nodes/abstract.py`), using `prompt.to_string()` for the prompt and the existing `extract_llm_output_content` helper for the output. Covers all LLM nodes across packages (single choke point).

### 2. Per-vector-store retrieval settings
- Moved `default_k` / `k_max` / `k_inc` into `VectorStoreInfo` (`utils_pkg/klea_utils/stores/config.py`) as optional per-store fields; `general.default_k` / `k_max` / `k_inc` remain as graph-wide fallbacks.
- Reworked `VSRetriever` (`utils_pkg/klea_utils/stores/retrieval.py`): single shared `self.k` replaced by a per-store current-k dict keyed `(domain, store.name)`; `inc_k()`/`reset_k()` operate on **loaded** stores only, each incremented by its own `k_inc` and capped by its own `k_max`; `retrieve()` passes each store its own `k`.
- `k_inc` plumbed through `GeneralConfig` -> `rag.py` -> `BaseLangGraph` -> `VSRetriever`.
- Mock-based unit tests added (no LLM, CI-safe); docs (tutorial + HF cookbook) and example configs updated to demonstrate per-store settings.

### 3. Logging: root logger + file logging (standard way)
- Replaced the per-module `setup_logger(name)` dual-stream pattern with a single process-wide `setup_root_logger(app_name, stderr_level, log_dir)` in `utils_pkg/klea_utils/plogging.py`. Idempotent; configures the **root** logger with INFO->stdout and non-INFO->stderr handlers plus an optional `RotatingFileHandler` (1 MB x 5) at `{data_dir}/{app_name}.log`.
- All library modules (`klea_utils.*`, `neuroml_mcp.*`) now use plain `logging.getLogger(__name__)` (no handlers, propagate=True). No `propagate=False` anywhere.
- **Noise control via levels, not enumeration:** root at INFO; only klea namespaces (`klea_utils`, `klea_rag`, `klea_code`, `neuroml_mcp`) and the `app_name` logger are raised to DEBUG. Third-party libs (fastmcp, mcp, urllib3, aiosqlite, langchain, ...) inherit root INFO automatically. This replaced an initial `CHATTY_THIRD_PARTY_LOGGERS` enumeration approach that proved fragile/unintuitive.
- Entry points wired with per-app+client identities: servers `klea-rag` / `klea-code`, clients `klea-rag-tui` / `klea-rag-web` / `klea-code-tui` / `klea-code-web`, `nml-mcp`, `klea-vs-create` (console-only). `run_repl` / `run_nicegui_app` gained an `app_name` param; `make_parser` gained `--app-name`.
- `BaseLangGraph.__init__` gained `log_file: bool = True` (file in `self.paths.user_data_dir`); tests pass `log_file=False`.
- Tests: new `utils_pkg/tests/test_plogging.py` (7 tests) + updates to `test_graph_base`, `test_tools_utils`, `test_neuroml_tools`.
- End-to-end tested by user: works; chatty third-party DEBUG filtered, klea DEBUG captured in file, third-party WARNING still recorded.

## Errors and Lessons

- Enumerating chatty third-party loggers is not the standard way and requires constant maintenance. The standard approach is root at a sane level + DEBUG on your own namespaces; the level hierarchy filters libraries for free.
- The api-router 422 test failures and the stores-retrieval env-var failure are pre-existing and unrelated to this work (verified by stashing changes and re-running).
- A per-module `propagate=False` was a workaround for a root-unconfigured setup; with root-level handlers it is unnecessary.
