## Objective

Close a gap in `klea-stores-create map-lint`: it did not check that the
metadata map's top-level keys are the actual source filenames, so an old
heading-keyed map was misread as "201 files needing review" instead of
being flagged as structurally wrong (store would fail on it).

## Completed

- Reproduced the gap with three metadata-map variants in `tmp/osb-docs/`
  (our generated template, a newer single-page url map, and an old
  heading-keyed url map) -- the old map's real problem (keys are heading
  titles, not filenames; values are flat metadata dicts with no
  `DEFAULT`) was invisible to the linter.
- `map_lint` now takes `source_files`; `missing_keys` (source file with
  no map entry = fatal, store raises ValueError) and `unknown_keys`
  (map keys that aren't source files = stale/heading-keyed) are
  reported.  Old flat-format entries get a single structural message
  instead of per-heading "missing: ..." noise.  Report renders both new
  sections; the command prints the full report first and exits non-zero
  when any `missing_keys` exist (no early stop).
- Strict parity decision: expected filenames = `find_source_files` of
  the source dir minus the linted map file itself -- exactly what the
  store step ingests (the cache is hash-keyed and cannot enumerate
  filenames; `_find_files` remains the source of truth).
- Extracted `find_source_files` out of `StoresBuilder` into
  `klea_utils/stores/utils.py` so `map-lint` no longer instantiates a
  builder: `utils.py` is now import-light (`Document` moved under
  `TYPE_CHECKING`; `CACHE_DIR_NAME`/`TEMPLATE_FILE_NAME` moved here from
  `ingestion.py`), and `StoresBuilder._find_files` is a thin delegate.
  This also removed "StoresBuilder initialised" / NumExpr noise from the
  lint output.
- Docs/CHANGELOG updated (`docs/tutorials/create-and-use-rag.rst`,
  `docs/concepts/rag.rst`, `CHANGELOG.md`).  The CLI/API reference pages
  pick up the changes automatically via `.. typer::` / `.. automodule::`.

## Errors and Lessons

- `click.exceptions.Exit` subclasses `RuntimeError`, so a `typer.Exit(1)`
  raised inside the CLI `try` was being swallowed by the trailing
  `except Exception` and re-raised as a misleading "Failed:" log; the
  `except typer.Exit: raise` guard (already used by `store`) is required.
- `.txt` is a docling-supported extension -- the unsupported-extension
  test fixture must use a truly unsupported suffix (`.xyz`).
- When piping a CLI through `grep`, `$?` is grep's exit status, not the
  CLI's; capture the CLI exit code separately (PIPESTATUS / redirect to
  a file) when asserting non-zero exits.

`--debug` previously meant "auto-reload" on the NiceGUI web clients and

## Errors and Lessons (second task)

- `logging.getLevelName` returns the *int* for a known string name
  (`getLevelName("DEBUG") -> 10`) but the string `"Level <name>"` for an
  unknown name -- the `isinstance(level, int)` + range guard is what
  separates valid from invalid.  The Python docs wording is misleading.
- An early `return int(raw)` for the numeric env path bypassed the
  range check, so `KLEA_LOG_LEVEL=999` returned 999; restructure so all
  paths (name and numeric) validate the range.
- `klea-stores-create map-lint` emits no DEBUG records in its normal
  path and writes no rotating log file (only `log_dir`-driven apps do),
  so the "debug on console / debug in file" E2E checks were verified
  via `setup_root_logger(log_dir=...)` directly and the unit tests
  rather than the map-lint CLI.
- `mcp_cli` imports `setup_root_logger` lazily, so the test must
  monkeypatch `klea_utils.plogging.setup_root_logger` (not the
  `main` module attribute); and stubbing `asyncio.run` alone left a
  `create_server` coroutine never-awaited, so `create_server` must also
  be stubbed.
