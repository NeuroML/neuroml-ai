## Objective

Make the RAG (and Code) clients usable as a single local command: `klea-rag cli`
/ `klea-rag web` should start a server automatically when none is running,
instead of requiring a separate `klea-rag-serve` step for individual local
users.  Includes a CLI restructure, shared server-spawn machinery, a test
suite, docs updates, and a small module relocation.

## Completed

### 1. Server spawn machinery (`utils_pkg/klea_utils/api/server.py`)
- `spawn_server(app_module, host, port, timeout=180)` context manager: pre-probes
  `/health/ready` (reuse an already-running server -> yields `None`, no lifecycle
  ownership); otherwise spawns `python -m uvicorn <module> --no-access-log`,
  waits via a short fast-fail window (instant-crash detection) then a long
  retrying wait, and terminates the spawned process on exit.
- `split_server_url(url, default_port)` and `is_loopback_host(host)` helpers.
- stdout/stderr inherited (startup errors visible); access logs disabled
  (`--no-access-log`) to keep the shared-terminal UX clean; full logs stay in
  the server's rotating file.

### 2. `check_api_is_ready` rework (`utils_pkg/klea_utils/api/utils.py`)
- Refactored the static `@retry` decorator into `tenacity.AsyncRetrying`
  (`_make_retryer`) so retries are parameterizable.
- `check_api_is_ready(url, attempts=None, timeout=180.0)`: `attempts` overrides
  to a count bound (fast `attempts=1` probes); default is a time-based
  `stop_after_delay(180)` so slow server init (MCP servers, model downloads)
  is not given up on.  All clients inherit the longer budget automatically.
- Removed legacy `klea_utils/api.py` (shadowed by the `api/` package, dead code,
  duplicate of `api/utils.py`); updated `utils_pkg/AGENTS.md`.

## Errors and Lessons

- **Typer group options are a discoverability trap**: flags on the callback do
  not show up in subcommand `--help`.  Model A (top-level flags + default
  subcommand) looked "normal" but confused users; per-subcommand flags are the
  right call for this app.
- Callback options must precede the subcommand (`klea-rag --server X web`);
  `klea-rag web --server X` fails.  Dual-definition (flag on both callback and
  subcommand) silently ignores the top-level value for web - a footgun.
- Calling a typer-decorated function directly yields `OptionInfo` objects, not
  defaults; default-to-cli needed the logic extracted into plain helpers.
- A single `typer.Option(...)` instance can be safely reused as the default for
  two different subcommands (probe-verified) - avoids duplicating shared flag
  definitions in the factory.
- pytest captures log records but displays only WARNING+ by default; set
  `log_level = "DEBUG"` in `[tool.pytest.ini_options]` to see test debug logs
  in failure reports.  This also surfaces third-party DEBUG noise (e.g.
  `faker.factory`) on failures.
- pyright flags `BaseHTTPRequestHandler.log_message` overrides typed with bare
  `*args`; annotate `def log_message(self, format: str, *args: Any) -> None`.
- In `test_run_web`, the command asserted is already `shlex.split`, so quotes
  are stripped (assert `--app-name klea-rag-web`, not the quoted form).
- Some LSP "Undefined name" errors during multi-edit sequences were stale; the
  files were correct - verify with `ty` rather than trusting editor diagnostics.
- `with spawn_server(...) as proc` rebinds the name over a Mock -> use a
  separate `mock_proc` name so type-checked assertions on the mock are valid.
