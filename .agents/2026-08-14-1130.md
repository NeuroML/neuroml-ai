### Fixes

- **Cache pruning**: orphaned `.klea-cache` entries (hash no longer
  matches any source file) are auto-removed at the end of every
  `chunk_all` call, so the cache mirrors the source dir and users never
  hand-clean it.
- **`map-lint`**: new LLM-free metadata-map linter (`map-lint` CLI +
  auto summary after `chunk`) flagging missing fields, suspicious
  titles/DOIs, year-vs-filename mismatches, stale `venue`, excess
  `url*` keys, and placeholder counts.  Shared stored-metadata schema
  moved to a lightweight `stores/metadata.py`.
- **Metadata resolution**: heading-map entries are now gap-fill merged
  over `DEFAULT` (heading keys win, `DEFAULT` fills the rest); empty
  `{}` placeholders fall through to `DEFAULT` instead of stripping it.
  This also strengthens the metadata filter (year/journal now reach more
  chunks).
- **Reference serialization**: `serialize_vs_retrieval` renamed
  `serialize_reference_material`.  Output is grouped by source file with
  shared bibliographic fields emitted once on a source header, chunks
  numbered beneath, each with its own inline relevance score; a `url*`
  is hoisted only when the whole file shares it, differing urls stay per
  chunk.  Grouping vs. scores kept separate so position never reads as
  relevance.

### Docs

- New "Reference material for the answer LLM" concept section in
  `rag.rst`; map review + `map-lint` + cache-pruning notes; CHANGELOG
  entries for all fixes.  Docs build (`make html`) passes.

## Errors and Lessons

- Real E2E testing surfaces design issues unit tests miss: e.g. empty
  map placeholders silently stripped `DEFAULT` metadata, and per-chunk
  repeated metadata bloated the LLM context.
- Empty `{}` in a metadata map is falsy -- returning it from the resolver
  meant `if meta:` skipped the metadata update entirely.
