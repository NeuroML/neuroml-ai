**Authoring agent:** opencode

## Objective

Replace env-file `*_APP_CONFIG_FILE` config selection with profile-based
lookup (`--profile <name>` loads `<name>.json`), plus `--profile template`.

## Decisions and outcomes

- Profiles resolve CWD-first, then the per-app platformdirs config dir.
- `--profile` is carried into the server via the existing
  `KLEA_AGENT_APP_CONFIG_FILE` / `KLEA_RAG_APP_CONFIG_FILE` env var (process
  env beats the env file in pydantic-settings), so no new config env var.
- `--profile template` scaffolds a ready-to-fill config into CWD (refuses to
  overwrite); RAG template includes an `ExampleDomain` placeholder.
- Implemented incrementally across utils/agent/rag; all committed except the
  `deployments/huggingface` submodule edits.

## Errors and lessons

- **Typer single-command collapse**: a `Typer()` with one command becomes a flat
  CLI, so `klea-rag-serve serve <opts>` fails (only `--help` works); the
  canonical form is `klea-rag-serve --host ... --profile ...`. Pre-existing
  docs/error messages referenced the bogus `serve` subcommand -- corrected and
  documented with a code comment.
- **Docs build broken in the dev venv** (pre-existing): sphinx 9.1.0 +
  sphinxcontrib-typer 0.8.1 incompatibility, reproduced in a minimal project.
  Deferred; likely needs version pins in `requirements-docs.txt`.
- Installing `requirements-docs.txt` replaced editable dev installs with stale
  copies (rag tests imported an old `klea_rag.config`). Restored with
  `uv pip install -r requirements-dev.txt --reinstall`. Build docs in a
  separate env, or reinstall dev editable afterwards.
