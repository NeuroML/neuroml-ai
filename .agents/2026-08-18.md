# Session: 2026-08-18-1729

**Authoring agent:** opencode
**Model:** deepseek-v4-flash

## Objective

Three linked pieces of work in the `utils_pkg`, all about making LLM
invocations reliable for reasoning-capable models on custom endpoints: (1)
fix a bare-URL linkification bug in the NiceGUI runner, (2) close a
truncation retry gap and make the retry ceiling endpoint-aware, (3) get the
live `/models` probe working for *native* providers without hardcoding
endpoint URLs.

## Completed

- **Linkify** (committed): replaced the hand-rolled `_BARE_URL_RE` regex with
  `klea_utils/ui/linkify.py` (linkify-it-py, added to the `nicegui` extra).
  Protects existing `[text](url)` markdown spans; 13 tests.
- **Truncation retry gap**: `openai.LengthFinishReasonError` was classified
  `UNKNOWN` and never retried; added `_LENGTH_TRUNCATION_PATTERNS` and wired
  `LENGTH_TRUNCATION` into `_invoke_with_retries`.
- **Retry ceiling / reasoning headroom**: retry grows the window in two
  bounded phases instead of an exponential ladder: a linear phase
  (`+2048` up to 16384) for models cut off just short of finishing, then
  fixed `+32768` steps up to the output ceiling
  (`MAX_OUTPUT_TOKENS_CEILING=32768`, or the endpoint headroom when
  advertised). `MAX_TRUNCATION_RETRIES` raised to 15 (covers the full
  climb to a 262144 context; bounds hallucination loops). No doubling:
  vLLM allocates KV-cache against `max_tokens`, so exponential growth
  spikes reservations, overshoots the real need, and overpays loops.
  The old one-shot "jump" is gone; `_jump_output_target` now only
  supplies the grow-ladder ceiling. Bumped small-output node defaults
  (GenerateRetrievalQuery, ClassifyQuestion, Guard) from 1024 to 2048.
- **Endpoint-aware retry ceiling**: `probe_endpoint_model_limits` in
  `models_catalog.py` does `GET {base_url}/models` for `max_model_len`
  (total context), in-memory cache 12h TTL keyed by `(base_url, model)`.
  `resolve_output_token_limit` gained `use_endpoint`: normal path stays on
  offline models.dev (mainly for the HF whole-window reservation); retry
  shrink/grow use the live endpoint.
- **Input-estimate safety factor**: `estimate_input_tokens` now inflates
  the char-based estimate by 5% (`math.ceil(chars/4 * 1.05)`). A raw
  estimate undercounted the server tokenizer by one token (2434 vs 2435),
  pushing the last-ditch jump target one token over context and 400ing
  (E2E observed). The factor is proportional to prompt length, not a
  hardcoded token margin.
- **Native-provider endpoint resolution** (resolves the "open question" from
  the morning): new `resolve_langchain_endpoint` in `llm.py` materialises the
  concrete model via langchain's private `_ConfigurableModel._model(config)`
  (cheap -- already called on every `ainvoke`, no network) and cycles a list
  of endpoint attributes (`openai_api_base`, `api_base`, `endpoint`,
  `anthropic_api_url`), taking the first string set. No per-provider map, no
  hardcoded URLs. `_update_output_window` stores the resolved `base_url` back
  into the configurable dict when missing, so both the shrink/double resolver
  and the jump target use it. The probe gate was relaxed to any provider with
  a base_url (not just `openai`); non-OpenAI-shaped `/models` responses just
  return None and fall back to the catalog.
- **Auth fix**: probe api key falls back to the env var the langchain SDK for
  that provider actually reads, via `_langchain_provider_api_key_env`
  (`{PROVIDER}_API_KEY`, with a `mistralai -> MISTRAL_API_KEY` alias). This
  also fixed a pre-existing bug where the mistral probe derived
  `MISTRALAI_API_KEY` (which the SDK does not read) -- exposed by the gate
  relaxation.
- **Naming** (per review): `get_model_limits` -> `get_catalog_model_limits`,
  `get_endpoint_model_limits` -> `probe_endpoint_model_limits` (verb + source
  both contrast). Removed the `get_model_output_limit` /
  `get_model_context_limit` convenience wrappers (test-only; tests now read
  `ModelLimits` fields directly).

## Errors and Lessons

- models.dev's `limit.output` is per-deployment config, not a model property;
  the same model ranges 32768-262144 across providers. The endpoint exposes
  only `max_model_len` (no separate output cap), so `context - input` is a
  physical max, not a real output limit -- fine for the grow-ladder ceiling
  ("trust the server" semantics).
- Exponential `max_tokens` growth is bad for this deployment: vLLM
  allocates KV-cache/scheduling resources against the requested
  `max_tokens`, so doubling spikes reservations, overshoots the real need,
  and a request asking for a huge window can run very long even before it
  completes. Replaced with the two-phase bounded ladder (linear, then
  fixed large steps).
- "Continue from the partial output" retries are NOT possible for the
  UCL model: its streaming/structured path raises
  `LengthFinishReasonError` with no partial content, so there is nothing
  to send back. Every retry regenerates from scratch -- a real cost for a
  model that thinks to tens of thousands of tokens (an 8k rung already
  took ~52s; a ~130k request was still running).
- The `/models` probe needs auth: for a `custom:` model, `api_key` is not in
  `config["configurable"]` (only the OpenAI SDK env fallback makes
  completions work), so the raw httpx probe 401'd. Do NOT try all `*_API_KEY`
  env vars against an endpoint (leaks provider A's credential to provider
  B's server); derive only the var matching the known `model_provider`.
- `_ConfigurableModel._model()` is a private langchain API, but Klea already
  depends on `_ConfigurableModel` semantics (invoke builds the concrete model
  on every call), so calling it for introspection adds zero marginal cost.
  Concrete class construction opens no sockets (httpx client objects only;
  openai's default client is lru_cached, anthropic's is a cached_property).
- `response_metadata["model_provider"]` is unreliable (mistral/groq don't
  populate it; deepseek reports two values) -- `model_provider` from `config`
  is the reliable source.
