### 6. Classifier structured-output hardening
- While testing with `gpt-oss-20b`, the classifier's LLM echoed the embedded
  output schema back instead of returning a classification
  (`{"query_domains": ["NeuroML"]}`). Root cause: the model is weak at
  schema-guided output, the endpoint evidently does not enforce
  `response_format` for it, and the prompt shows only the raw schema with
  no worked example. Fallout: the garbage parsed into
  `QueryDomainSchema(query_domains="undefined")` -- a *string* default for a
  `list` field (`graph/base.py` `create_model`) -- and `_update_state`
  iterated the string char-by-char, silently routing everything to
  "undefined".
- Fixed the default to `["undefined"]` and added `Field(validate_default=True)`
  so pydantic rejects a mistyped default at construction. Audited other
  pydantic defaults and added `validate_default=True` to the siblings:
  `rag_pkg/klea_rag/schemas.py` `next_step` (Literal) and `query_domains`
  (list), `code_pkg/klea_code/schemas.py` `StepSchema.status` and
  `PlanSchema.status` (Literals).
- Note: pydantic v2 does NOT validate field defaults by default
  (`validate_default=False`); a string default for a list field is accepted
  silently, and at parse time a string is rejected for a `list` field. This
  is why the mistyped default went unnoticed.

## Errors and Lessons

- **Stale MCP server on e2e**: after the docstring rewrites, `tools_info`
  still showed the old descriptions because a running `nml-mcp` process
  predated the edits (editable install picks up changes only on restart).
  The new `Parameters:` bullets were live (RAG-side `build_tool_description`)
  while descriptions were stale (MCP-side). Restart the MCP server after
  changing tool code.
- **fastmcp behaviour**: a single pydantic `BaseModel` tool param is NOT
  flattened into the schema (nested `{"params": ...}`) -- reject that option
  for tool input models. Explicit `Field(description=...)` wins over
  docstring `Args:` parsing when both are present.
- **Docs build pre-existing break**: `make -C docs html` fails under Sphinx
  9.1.0 (new CLI, `-M` gone) at `cli/klea-code.rst`
  (`sphinxcontrib.typer` incompatibility). Use
  `sphinx-build docs docs/_build/html` or docutils to validate single pages.
- **Weak models + structured output**: small models (e.g. `gpt-oss-20b` on
  HuggingFace) may echo the schema shown in the prompt instead of returning
  an instance, especially when the endpoint does not enforce
  `response_format`. A `20b` model is not necessarily reliable at this; the
  prompt currently shows only the raw schema with no example. Decided NOT to
  add a worked example (the codebase already adds a textual JSON description
  when a model lacks structured-output support); model choice is the operator
  lever.
