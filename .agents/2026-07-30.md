### Token usage tracking
- **`rag_pkg/schemas.py`**: Added `TokenUsage(BaseModel)` with `input_tokens`/`output_tokens`/`total_tokens` and `usage_metrics: TokenUsage = TokenUsage()` field on `RAGState`.
- **`abstract.py`**: Added `_token_usage`, `_update_usage(output, state)` hook (extracts `usage_metadata` from `AIMessage`, adds to state's running total), `_get_usage()` (returns `NodeStreamData` with display string), `_update_usage_metrics()` (injects token dict into state updates). Emits `"usage"` event in `_post_exec_stream()`. Added `"usage"` to `NodeStreamEvent.type` `Literal`. Fixed dict unwrap for structured output path.
- **`base.py` graph runner**: Added `"usage"` to the `event_type` set in `run_graph_astream_events()`.
- **`runner.py` frontend**: Handles `"usage"` events in `_do_stream()`, stores in `current_chat["token_usage"]`, refreshes status pane. Displays `"X in / Y out"` as `text-xs text-grey-5` below model info.
- **`sse.py` and `base.py` docstrings**: Documented `usage` event type.

### Key design decisions
- Token usage is accumulated in graph state (`usage_metrics`) per thread, persisted by LangGraph checkpoint DB automatically. Not stored in session DB.
- Provider token availability varies: vLLM/Qwen returns `token_usage: None`, others (Ollama, HF, OpenAI) populate `usage_metadata`. Code handles gracefully (no event emitted when unavailable).
- `_update_usage` and `_update_usage_metrics` kept as separate methods: accounting vs state plumbing.
- `self._token_usage` is node-local (set per `execute()` call), safe under LangGraph's per-invocation task scope.

## Errors and Lessons

- **`_linkify_md()` false negative**: The original negative lookbehind `(?<!\()` only protected the `(url)` part of `[text](url)`. URLs inside `[text]` that were themselves URLs (e.g. `[url](url)`) got re-wrapped, producing broken markdown. Fixed with alternation regex.
- **Streamlit removal dependency ripple**: `streamlit` was in `install_requires` of both `rag_pkg` and `code_pkg`, requiring setup.cfg edits in both.
- **`AIMessage.usage_metadata` vs structured output dict**: `_invoke_llm` returns `{"raw": AIMessage, ...}` when `with_structured_output(include_raw=True)` is used. The `isinstance(output, AIMessage)` check missed this. Fixed with early unwrap.
- **Type checker frustration with `hasattr`**: `hasattr(state, "usage_metrics")` doesn't narrow types for the type checker. Switched to `getattr(state, "usage_metrics", None)` pattern.
- **CSS class `.md-div` doesn't exist**: NiceGUI's `ui.markdown()` generates `.nicegui-markdown`, not `.md-div`. Fixed multiple selectors.

## Open Questions

- `target="_blank"` on links: MutationObserver gets overwritten by Vue reactivity. Server-side HTML injection works but produces ugly output when LLM also emits markdown links. Skipped.
- Token usage per "today": considered but dropped (requires timestamped checkpoints and daily reset) -- standard practice for tools like OpenCode/ChatGPT is session-only totals.
