**Authoring agent:** opencode

## Objective

For `klea-stores-create`, decide per-PDF whether OCR is needed before
ingesting a full academic bibliography, without guessing by publication
year. Plus: warn when a PDF converts to zero chunks, and make the
metadata map's autogenerated heading-chain keys actually consumable.

## Completed

- `pre-check <dir> [--organise]`: classifies PDFs by embedded text layer
  (pypdfium2) into needs-OCR vs text-based; `--organise` copies (never
  moves) into `ocr/`/`no-ocr/` subdirs and prints the recommended
  chunk+store workflow (both store runs target the same collection so
  they merge). New module `klea_utils/stores/precheck.py`.
- Empty-chunk warnings on both `chunk` (convert path) and `store`
  (cache path) in `ingestion.py`, pointing at re-running with OCR or
  `pre-check`.
- Fixed `_resolve_metadata`: previously only matched individual
  headings, so the template's full-chain keys (e.g. `"Chapter >
  Section"`) were never looked up. Now matches most-specific-first: full
  chain, then shorter suffixes, then shallower ancestor chains, then
  DEFAULT. A leaf section with no metadata inherits its nearest
  ancestor's (per user requirement). Added fall-through debug logging so
  resolution is traceable.
- Docs (`cli`, `concepts/rag`, `tutorials/create-and-use-rag`) and
  `CHANGELOG.md` updated.
- `store-lint <corpus.pkl> [--samples N]`: LLM-free post-store review of
  the BM25 corpus pickle (summary, suspicious chunks -- near-empty text /
  missing metadata -- structural checks: no `file_name`, invalid types).
  `--samples` prints N evenly-spaced windows of contiguous chunks (3 each,
  `select_sample_windows`) so a user can eyeball chunking/metadata without
  unpickling the file. Auto-printed at the end of `store`. New module
  `klea_utils/stores/postcheck.py`.

## Errors and Lessons

- The bare-PDF fixture yields no extractable text with pypdfium2; a
  text-bearing test fixture needs a Resources dict + a Helvetica Type1
  font + a content stream (`BT ... Tj ET`).
- `organise_directory` must treat a PDF as no-OCR only when explicitly
  classified so; anything unclassified (read failure) routes to `ocr/`.
- A `typer.Exit(0)` inside a `try` was caught by the trailing
  `except Exception` and re-raised as exit 1; must re-raise `typer.Exit`
  first (pattern already used by the `store` command).
- `test_chunk_all_prefills_metadata_template` fails on this machine
  without `DOCLING_DEVICE=cpu` (Quadro P1000/CUDA cc 6.1 issue
  documented in AGENTS.md) -- environmental, not a regression.
