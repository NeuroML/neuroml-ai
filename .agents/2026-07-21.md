## Objective (afternoon)

Debug streaming event delivery: the frontend progress label always lagged by one node (showed previous node's name during the current node's execution). The root cause was that `_invoke_llm` used `llm.invoke()` (synchronous, blocking) inside an `async def execute()`, which blocked the event loop from processing `call_soon_threadsafe` callbacks from `write_custom_stream` and LLM token handlers until the entire node completed.

## Completed (afternoon)

- **Identified root cause**: `llm.invoke()` is a synchronous blocking call. When called inside an async task, the event loop cannot process any queued callbacks (including `call_soon_threadsafe` from `get_stream_writer()`) until the task yields or completes. This caused ALL streaming events (progress, tokens, info, debug) to be buffered until the node's LLM call returned.

- **Created timing debug script** (`utils_pkg/tests/debug_stream_timing.py`) — a toy LangGraph with custom nodes that emit `write_custom_stream` before and after a sleep. Confirmed:
  - With `await asyncio.sleep(N)` (non-blocking, yields to event loop): first event arrives immediately at `t_start`. Second event arrives at `t_end`.
  - With `time.sleep(N)` (blocking, like `llm.invoke()`): ALL events arrive at `t_end` — including the first event emitted BEFORE the sleep.
  - Conclusion: any blocking call in an async node prevents ALL event-delivery callbacks from being processed until the call returns.

- **Applied fix** in `utils_pkg/klea_utils/nodes/`:
  - `abstract.py:190`: `await self._invoke_llm(...)` — awaits the async method
  - `abstract.py:272`: abstract `_invoke_llm` changed to `async def`
  - `base.py:147-157`: `_invoke_llm` changed from `llm.invoke()` to `await llm.ainvoke()`

- **Verified no other blocking calls**: audited every method in the `execute()` template chain (`_pre_exec` → `_configure_llm` → `_invoke_prompt` → etc.). All are fast (microseconds, pure Python or tiny file I/O). No other methods need async conversion.

- **Remaining work**: `code_pkg` nodes (GoalSetter, Planner, etc.) do not emit info/debug events yet — they need the same treatment as RAG nodes.
