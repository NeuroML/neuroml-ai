**Authoring agent:** opencode

## Objective

LLM model setup refactor: migrate from hardcoded c_model/r_model/g_model instance vars to a dict-based LLMModel container with live entry references for runtime model switching. Also fix check_model_works to avoid leaking kwargs to provider clients.

## Completed

- **init_chat_model for HuggingFace** — replaced manual ChatHuggingFace(llm=HuggingFaceEndpoint(...)) construction with init_chat_model(model_provider="huggingface", backend="endpoint", ...). No custom wrapping needed.
- **Unified configurable_fields** — defined `_COMMON_CONFIG_FIELDS` tuple, extended per-provider (HF gets "provider", "backend", "huggingfacehub_api_token", "max_new_tokens"; non-HF gets "num_predict" for Ollama). Both branches now support "model", "model_provider", "temperature", "max_tokens", "api_key", "base_url".
- **check_model_works fix** — uses `_llm_type` to pick the right token param per provider (max_new_tokens for HF, num_predict for Ollama, max_tokens for others), passes via config["configurable"] instead of invoke kwargs to avoid Client.chat() TypeError. 5-token limit.
- **LLMModel class** — Pydantic model in `base.py` holding `instance` + `config_template` + `build_config()` method. Replaced `self.c_model` with `self.llm_models: dict[str, LLMModel]`.
- **model_type class var** — added to all 12 node subclasses (chat/plan/guard roles). Node resolves its own model via `self.llm_models[self.model_type]`.
- **AbstractLLMNode + BaseLLMNode** — __init__ accepts `llm_models: dict[str, Any]` instead of raw model + temperature. Added KeyError guard for missing model_type. `_invoke_llm` now uses `build_config()`.
- **Orchestrator _setup_models()** — both KleaCode and RAG populate `self.llm_models` dict with LLMModel entries. Removed `self.r_model` / `self.g_model` declarations. Node constructors pass `llm_models=self.llm_models`.
- **model_config caching** — `AbstractLLMNode.__init__` computes `self.model_config = entry.build_config(...)` once to avoid per-invoke deepcopy + dict merge. (Will be replaced by live entry refs in a future step.)
- **Live entry references** — nodes store `self._llm_entry` instead of caching `model_inst`/`model_config`. `_configure_llm` and `_invoke_llm` read instance and config live from the entry each invocation.
- **`model_overrides_ctx` contextvar** — defined in `graph/base.py`, set in `api/chat.py` endpoints before graph calls, read in `nodes/base.py` `_invoke_llm`. Carries per-session model overrides (api_key, model, provider) without plumbing through node signatures.
- **Per-session model endpoints** — replaced global `POST /models/{role}` with `GET /session/{session_id}/models` and `POST /session/{session_id}/models/{role}` in `api/models.py`. Settings stored in `app.state.sessions[thread_id]`.
- **Removed dead code** — `LLMModel.rebuild()` and `BaseLangGraph.update_model()` removed since all model switching is now per-session via contextvar overrides.
- **Fixed `session_id` consistency** — `query` and `query_stream` both use the same raw session_id for settings lookup (no `session_` prefix mismatch). Session entries always initialized as dict, not bool.

## Errors and Lessons

- `init_chat_model` for HuggingFace calls `ChatHuggingFace.from_model_id(model_id=model, backend="endpoint", **kwargs)` — provider-specific kwargs like "provider", "huggingfacehub_api_token" flow through correctly.
- HuggingFace's `HuggingFaceEndpoint` uses `max_new_tokens`, not `max_tokens`. Passing `max_tokens` as a configurable is silently ignored.
- `_ConfigurableModel` filters configurable fields — only fields listed in `configurable_fields` are accepted from runtime config. Provider-specific token params must be in the list.
- Setting attributes on `_ConfigurableModel` wrapper has no effect — `invoke()` creates a fresh inner model. Pass fields via `config["configurable"]` instead.
- LSP errors for `init_chat_model` overloads are false positives — the overloads don't know about provider-specific **kwargs but work at runtime.

## Deferred: Part B — backend-managed sessions (implement after merge)

### Why

`runner.py` has `_sessions: dict[str, dict] = {}` — a module-level global shared by all users. User A sees User B's sessions. For a HuggingFace demo this is unacceptable.

### Solution

New `api/sessions.py` with a `SessionManager` class keyed by `f"{user_id}:{session_id}"`. `user_id` is a random UUID stored in NiceGUI's `app.storage.user` (per-browser via localStorage). No auth — enough isolation to prevent casual leakage.

| Endpoint | Purpose |
|----------|---------|
| `GET /sessions/{user_id}` | List this user's sessions |
| `POST /sessions/` | Create a new session |
| `DELETE /sessions/{user_id}/{session_id}` | Delete a session |
| `PATCH /sessions/{user_id}/{session_id}` | Rename a session |
| `POST /sessions/{user_id}/{session_id}/pin` | Toggle pin |

Wire into both `code_pkg/api/main.py` and `rag_pkg/api/main.py`.

Refactor `runner.py` to:
- Remove the module-level `_sessions` dict
- Replace all local CRUD operations with `httpx` calls to the backend endpoints
- Add `user_id` alongside `session_id` in `app.storage.user` on first visit

When auth is added later, `user_id` graduates from a random UUID to the auth provider's identity. The `SessionManager` keying (`f"{user_id}:{session_id}"`) stays identical.
