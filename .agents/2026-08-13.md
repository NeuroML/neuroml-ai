## Completed

### RAG retrieval depth

- **Single k-increment**: confirmed both `RouteEvaluator` and
  `RetrieveInfoNode` called `inc_k()` per cycle (k jumped 5 -> 7 -> 9 -> 10).
  Added non-mutating `can_inc_k()` to `BaseKleaRetriever`; the router routes
  with `any(r.can_inc_k() ...)` (inlined after review) and never mutates k;
  `RetrieveInfoNode` is the sole `inc_k()` caller.
- **Size-based context budget**: confirmed `rrf_merge(..., num_refs_max=10)`
  truncated fused results to 10 per domain regardless of k, and
  `reference_material` was replaced (not accumulated) each pass. Replaced the
  fixed 10-doc cap with `GeneralConfig.max_refs_size` (default 20000 chars);
  new `truncate_reference_material()` applies a single global char budget
  across domains in RRF order, always keeping the first doc that crosses the
  budget. k now controls fetch depth, `max_refs_size` controls what reaches
  the answer LLM. `k_max` kept as a per-pass fetch cost cap (its docs wording
  corrected -- it is NOT the context limiter).
- Docs (`create-and-use-rag.rst`, `huggingface.rst`) and `CHANGELOG.md`
  updated.

### Metadata-filtered retrieval

- Added a backend-agnostic metadata filter DSL so a query can constrain
  retrieval by year/journal/authors/keywords ("nature papers 2020-2025").
- `GenerateRetrievalQuery` emits structured output (`RetrievalQueryOutput`)
  and is the sole writer of `RAGState.retrieval_query`.
- `klea_utils/stores/filters.py`: normalized DSL canonicalized to
  single-operator clauses + `$and` (chromadb and langchain_postgres both
  reject multi-op/multi-key top levels -- verified empirically); translators

- Retrievers accept `metadata_filter=`; vector stores apply the native filter

### Ingestion alignment + metadata key policy

- **`venue` -> `journal`**: renamed across `BiblioRecord`, the DOI-service
  normalizers, extraction output, and tests so the stored key matches the
  filter schema. No cache shim (stale caches regenerated by `--force`).
- **Key policy + map enforcement**:
  - Whitelist (`ALWAYS_STORED_METADATA_KEYS` + `url*`) and drop set
    (`STORE_DROPPED_METADATA_KEYS` = `source_path`/`source_type`/
    `source_url`); `_`-prefixed keys always dropped. Applied at fold and store
    time.
  - `chunk_all` errors when a source file is missing from the map.
  - `store` is strict: requires a map (explicit or template), aborts on
    missing/empty map or missing file.
  - `build` is one-shot: generates and consumes the template internally (no
    review step), overwriting any existing template by design; the reviewed
    flow is `chunk` -> edit -> `store`.
- Decisions: typed filter schema (not free-form); no explicit filter entry
  point yet (deferred to agent integration); BibTeX `venue` -> `journal`;
  stored-metadata key policy = whitelist + metadata-map pass-through; `.bib`
  as a metadata source parked.

## Errors and Lessons

- Tests using three documents with identical `page_content` silently collapse
  to one because `rrf_merge` dedupes by content -- use distinct content in
  retrieval tests.
- `any()` short-circuits: the router helper "asks every retriever" only when
  it mutates state; a pure check can short-circuit, so inline `any()`.
- httpx `verify` is client-level; neuroml-db.org has a broken cert chain, so
  its tools use a scoped `verify=False` client while web_fetch stays secure.
- Protocol with `**kwargs` is incompatible with httpx's named-param methods;
  enumerate params.
- "Verify then fall back to no-verify" == no verification (MITM forces the
  fallback) -- scope `verify=False` narrowly.
- `Sec-*` client hints must match the UA version; partial impersonation is
  worse than none.
