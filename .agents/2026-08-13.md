# Session: 2026-08-13

**Authoring agent:** opencode
**Model:** deepseek-v4-flash

## Objective

Investigate whether increasing the RAG retrieval depth (k) actually surfaced
newly retrieved documents, and fix the two bugs found: a double k-increment
per `retrieve_more_info` cycle, and a hardcoded 10-document cap that discarded
lower-ranked chunks once k grew past it.

## Completed

- Confirmed the cap bug: `rrf_merge(..., num_refs_max=10)` truncated the fused
  results to 10 per domain regardless of k, and `reference_material` was
  replaced (not accumulated) each pass, so docs ranked 11+ were never used.
  Also confirmed a double increment: both `RouteEvaluator` and
  `RetrieveInfoNode` called `inc_k()` per cycle (k jumped 5 -> 7 -> 9 -> 10).
- **Single k-increment**: added non-mutating `can_inc_k()` to
  `BaseKleaRetriever`; the router now routes with `any(r.can_inc_k() ...)`
  (inlined after review) and never mutates k; `RetrieveInfoNode` is the sole
  `inc_k()` caller.
- **Size-based context budget**: replaced the fixed 10-doc cap with
  `GeneralConfig.max_refs_size` (default 20000 chars). `rrf_merge` count cap
  is now optional; new `truncate_reference_material()` applies a single global
  char budget across domains in RRF order, always keeping the first doc that
  crosses the budget (never empty context). k now controls fetch depth,
  `max_refs_size` controls what reaches the answer LLM.
- Docs (`create-and-use-rag.rst`, `huggingface.rst`) and `CHANGELOG.md`
  updated; docs build green.

## Errors and Lessons

- A test using three documents with identical `page_content` silently collapsed
  to one because `rrf_merge` dedupes by content -- use distinct content in
  retrieval tests.
- `any()` short-circuits: the router helper "asks every retriever" only when it
  mutates state; a pure check can short-circuit, so inline `any()` and drop the
  module-level helper.

## Update (afternoon): metadata-filtered retrieval

**Objective:** let a query constrain retrieval by metadata (year range, journal,
authors, keywords) -- "nature papers between 2020-2025". Implemented as a
backend-agnostic filter DSL threaded through the RAG graph.

**Completed** (commits: `a598242`, `c9f5d17`, `fc95034`, `310e741`):

- `GenerateRetrievalQuery` switched from free-text to **structured output**
  (`RetrievalQueryOutput`: `search_query` + `year_from`/`year_to`/`journal`/
  `authors`/`keywords` + `to_metadata_filter()`). `RAGState.retrieval_query`
  is now this model; `InitRAGState` no longer resets it (the generator is the
  sole writer, writes a fresh instance each run).
- New `klea_utils/stores/filters.py`: normalized DSL
  (`{field: {op: value}}` + `$and`/`$or`). `validate_metadata_filter`
  canonicalizes to **single-operator field clauses + `$and`** (both chromadb
  1.5.9 and langchain_postgres reject multi-op field expressions and multi-key
  top levels -- verified empirically). Translators: `to_chroma_filter`
  (identity), `to_qdrant_filter` (`models.Filter` tree), `to_pgvector_filter`
  (`$contains` list-membership approximated as `$like` over the serialized
  JSON array), `translate_metadata_filter` (dispatch by store URI scheme),
  `filter_docs_by_metadata` (Python matcher for BM25).
- Retrieval threading: `BaseKleaRetriever.retrieve(..., metadata_filter=)`;
  VS applies the native `filter=` **inside** the ANN search; BM25 fetches a
  3x margin and post-filters. `RetrieveInfoNode` passes
  `state.retrieval_query.to_metadata_filter()`.
- E2E smoke test (`klea-rag cli --single-query "How do I visualize neuroml
  models"`, custom opencode.ai chat endpoint + ollama embeddings): graph in
  26.2s, structured output clean (`search_query='NeuroML model visualization'`,
  all filter fields null/empty -- no schema echo), grounded answer + 5
  references, evaluator 0.95 continue.

**Decisions:**

- Metadata field names follow BibTeX: `venue` -> `journal` (ingestion rename
  still pending, step 13); keep `authors`/`keywords`/`doi`/`url` (documented
  extensions).
- Filter schema is **typed fields**, not a free-form dict (the schema is
  injected into the prompt; a raw slot would confuse small models). No explicit
  filter entry point yet -- deferred to the agent-integration design.
- Stored-metadata key policy: **whitelist + metadata-map pass-through** --
  always store system+cascade keys, always drop `_`-prefixed/provenance keys,
  store whatever the researcher put in the metadata map (step 12).
- `.bib` as a metadata source parked (needs a `bib2map` converter; Crossref
  preferred as authoritative). Toy Qdrant/pgvector stores noted as future test
  fixtures (translators are currently structural-tested only).

**Errors and Lessons:**

- Empirically confirmed backend filter constraints (chromadb and
  langchain_postgres single-op + single-key-top-level) rather than assuming a
  shared DSL shape; the canonical form is what makes one filter work everywhere.
- `langchain_postgres` has **no** array-contains operator -> documented `$like`
  approximation.
- `rank_bm25` idf goes negative when a query term appears in >N/2 of a tiny
  corpus, and `_retrieve_from_store` drops `score <= 0` docs -- BM25 tests need
  realistic corpora, not identical-content fixtures.
- The logger formatter already prints `funcName`; don't repeat function names
  in messages, use the `{var = }` convention.
- bash `$` expansion mangles `$gte` etc. inside `python -c "..."` -- write
  throwaway probes to files.

**Notes:**

- Existing stores (nml-docs etc.) carry **no** `year`/`journal`/`authors`
  metadata (their maps were URL-only), so they cannot exercise filters -- the
  filter E2E needs a fresh sample store built from PDFs spanning years.
- The deployed nml-docs store still leaks internal keys (`_metadata_complete`,
  `_sources`) and `source_path`; step 12 + re-index addresses this.
