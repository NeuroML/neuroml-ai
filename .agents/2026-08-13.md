# Session: 2026-08-13

**Authoring agent:** opencode
**Model:** deepseek-v4-flash

## Morning: RAG retrieval-depth fixes

Fixed two retrieval bugs: a double `k`-increment per `retrieve_more_info`
cycle, and a hardcoded 10-doc cap that discarded lower-ranked chunks. The
count cap was replaced with a global character budget
(`GeneralConfig.max_refs_size`, default 20000) via
`truncate_reference_material()`; `k` now controls fetch depth and
`max_refs_size` controls what reaches the answer LLM. `RetrieveInfoNode` is
the sole `inc_k()` caller.

## Afternoon: metadata-filtered retrieval

Added a backend-agnostic metadata filter DSL so a query can constrain
retrieval by year/journal/authors/keywords ("nature papers 2020-2025").

- `GenerateRetrievalQuery` emits structured output (`RetrievalQueryOutput`)
  and is the sole writer of `RAGState.retrieval_query`.
- `klea_utils/stores/filters.py`: normalized DSL canonicalized to
  single-operator clauses + `$and` (chromadb and langchain_postgres both
  reject multi-op/multi-key top levels -- verified empirically); translators
  for chroma/qdrant/pgvector plus a Python matcher for BM25.
- Retrievers accept `metadata_filter=`; vector stores apply the native filter
  inside ANN search, BM25 post-filters.
- E2E smoke test green (custom opencode.ai endpoint + ollama embeddings).

Decisions: typed filter schema (not free-form); no explicit filter entry
point yet (deferred to agent integration); BibTeX field naming (`venue` ->
`journal`); stored-metadata key policy = whitelist + metadata-map
pass-through; `.bib` as a metadata source parked.

## Evening: ingestion alignment + metadata key policy

- **13 -- `venue` -> `journal`**: renamed across `BiblioRecord`, the
  DOI-service normalizers, extraction output, and tests so the stored key
  matches the filter schema. No cache shim (stale caches regenerated by
  `--force`).
- **12 -- key policy + map enforcement**:
  - Whitelist (`ALWAYS_STORED_METADATA_KEYS` + `url*`) and drop set
    (`STORE_DROPPED_METADATA_KEYS` = `source_path`/`source_type`/
    `source_url`); `_`-prefixed keys always dropped. Applied at fold time and
    at store time.
  - `chunk_all` errors when a source file is missing from the map.
  - `store` is strict: requires a map (explicit or template), aborts on
    missing/empty map or missing file.
  - `build` is one-shot: generates and consumes the template internally (no
    review step), overwriting any existing template by design; the reviewed
    flow is `chunk` -> edit -> `store`.
