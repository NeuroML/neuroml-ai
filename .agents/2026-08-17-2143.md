## Objective

Design and implement MCP tool infrastructure supporting multiple domains:
a shared, tag-configurable bundled tools server plus standard MCP
annotations, so RAG and agent deployments can enable the tools they need
per domain without editing server code.

## Completed

- Confirmed empirically that fastmcp 3.4.7 already supports per-server tool
  filtering via `include_tags`/`exclude_tags` on config entries, and that
  `FastMCP.tool()` accepts an `annotations` kwarg (both reached
  `list_tools()`).
- Implemented (incrementally, review/commit per step) the full plan:
  shared bundled server, tag-based filtering, standard annotations, docs.
- Maintained the agent/RAG config parity: a single `general` section on
  both apps hosts `bundled_tools` (agent on by default, RAG opt-in).
- RAG exposes the bundled server across all its domains (one shared client,
  no duplicate subprocesses).
- Standard MCP annotations adopted for the effect signal rather than a
  third tag axis; tags kept to scope + domain only.

## Errors and Lessons

- `mcp_pkg` tests initially failed because the package resolved
  `klea_utils` from a stale installed copy (old `registry.py` without
  annotations support); refreshing the editable install
  (`uv pip install -r requirements-dev.txt`) fixed it.  Lesson: refresh
  editable installs after changing shared-package internals.
- The editor LSP persistently flagged the new `klea_utils.mcp.server`
  module as unresolvable while runtime, `ty`, and pytest all resolved it --
  LSP index staleness, not a real error.
- fastmcp rewrites tool signatures on registration (moving Context after
  params), so tests must check parameter membership, not position.
- A latent flaky test surfaced from set-iteration order; fixed with set
  comparison.
- Docs build needs `sphinxcontrib-typer` (imports as `sphinxcontrib.typer`);
  `make html` needs `requirements-docs.txt` installed.  Was reminded to use
  `uv pip`, not `pip`.

## Notes

- Two-axis model settled and documented: tags = Klea's config filtering
  (which domain's tools); standard MCP annotations = universal behavioral
  contract (read-only/destructive) any host can enforce.
- Final tag vocabulary: scope `local`/`web` + domain/functional (`bundled`,
  `files`, `code`, `download`, `echo`, `neuroml`, `neuroml-db`, `osb`);
  no read/write/exec tag axis.
- Full verification green: 567 tests, `ty` at 29-diag baseline, all 6 CLIs
  start.  Only CHANGELOG left uncommitted at session end (reviewed).
