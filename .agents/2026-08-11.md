## Objective

Two threads: (1) `klea-stores-create` option clarifications, ending in a
folder-only Chroma contract; (2) the main feature -- a `biblio`
bibliographic-metadata extraction cascade that auto-pre-fills
`metadata-map.template.json` during chunking.

## Completed

- **Chroma folder-only**: verified chromadb hardcodes
  `chroma.sqlite3` (no filename knob), so stores are addressed by folder
  only. `--bm25-store` defaults to `<collection>.pkl` in cwd;
  `--collection` must match the store's `name` in the RAG config.
- **Test config** renamed `VS_TEST_CONFIG` -> `STORES_TEST_CONFIG` /
  `stores-tests.json`; `test_retrieval` extended to exercise BM25.
- **New `klea_utils/biblio` subpackage** (pdf/regex/doi are
  docling-independent, reusable):
  - `pdf.py` -- Info dict via pypdfium2 (already a docling dep, no new
    dependency)
  - `regex.py` -- keywords/authors/doi/url scans; hosts shared patterns
  - `doi.py` -- `DoiResolver`: Crossref/OpenAlex/Semantic Scholar,
    round-robin primary + fallback on 429, disk cache,
    `KLEA_INGEST_MAILTO` polite pool, `BiblioRecord` model
  - `docling.py` -- structured signals + first-page layout region
  - `extract.py` -- tiered cascade (doi-service > pdf-info > docling >
    layout-regex > regex), most-authoritative-first, plus shared core
    `extract_metadata_from_text` for cache hits; internal
    `_metadata_complete`/`_sources` keys never reach the LLM; abstract
    is completeness evidence only
- **Ingestion**: `chunk_all` pre-fills template `DEFAULT`; the cache
  persists `(docs, extracted)` so cache hits restore the full cascade
  (legacy caches fall back to text extraction with a warning).
- **OCR toggle**: `--ocr/--no-ocr` on all `klea-stores-create` commands;
  disabling OCR cut a text PDF conversion from >170s to ~127s.
- Traceable logging throughout (per-tier debug, resolution outcomes,
  incomplete-file warning, per-file summary).
- Docs: `rag.rst` cascade section, `api/utils/biblio.rst`, tutorial,
  CHANGELOG; `make html` verified with `requirements-docs.txt`.

## Errors and Lessons

- chromadb hardcodes the DB filename -- offer folder paths only.
- pypdfium2 `get_metadata_dict` drops custom Info keys -- scan the
  `Subject` value for an embedded DOI/URL.
- Docling CPU conversion is the bottleneck (~127 s/PDF, pre-existing);
  the biblio tiers add milliseconds.
- The cache-hit regex fallback used to degrade a good first-pass template
  -- fixed by persisting `(docs, extracted)`.
- `localonly` tests run in CI (not filtered); they self-skip only on
  ollama-connection failure -- AGENTS.md wording corrected.
