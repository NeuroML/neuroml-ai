### 2. Bibliographic metadata extraction (`klea_utils/biblio`)

New subpackage of reusable utilities (pdf/regex/doi are docling-independent):

- `pdf.py`: `extract_pdf_info` via **pypdfium2** (already a docling dep --
  no new dependency). Info dicts are sparse (eLife empty; PLOS CB has
  title/authors); DOI/URL found by scanning the `Subject` value, since
  pypdfium2 only returns the 8 standard Info keys.
- `regex.py`: `extract_regex_metadata` (keywords/authors/doi/url over the
  first ~3000 chars); hosts the shared `DOI_RE`/`URL_RE`.
- `doi.py`: `DoiResolver` -- Crossref/OpenAlex/Semantic Scholar,
  round-robin primary + fallback on 429, polite-pool `mailto` via
  `KLEA_INGEST_MAILTO`, disk cache, `BiblioRecord` pydantic model.
- `docling.py`: `extract_docling_structured` (title item, mimetype/uri,
  hyperlinks) + `extract_layout_region` (first-page header via bboxes).
- `extract.py`: tiered cascade `extract_metadata` (doi-service >
  pdf-info > docling > layout-regex > regex) plus shared core
  `extract_metadata_from_text` (used on cache hits). Internal
  `_metadata_complete`/`_sources` keys never reach the LLM; the abstract
  is completeness evidence only.
- `ingestion.py`: `chunk_all` pre-fills `DEFAULT`; the cache now stores
  `(docs, extracted)` so cache hits restore the full extraction; legacy
  caches fall back to text extraction (regex + pdf-info + DOI resolve)
  with a warning.
- **OCR toggle**: `StoresBuilder(do_ocr=...)` + `--ocr/--no-ocr` on all
  `klea-stores-create` commands; disabling OCR cut conversion of a text
  PDF from ">170s (stalled)" to ~127s.
- Traceable logging throughout (per-tier debug, resolved-DOI info,
  resolution-skip/fail warnings, incomplete warning, per-file summary).
- Tests per tier (mocked transports for the DOI APIs; synthetic docs +
  generated PDFs; real eLife/PLOS fixtures copied into `tests/`); 62
  non-`localonly` pass.
- Docs: `rag.rst` metadata-extraction section, `api/utils/biblio.rst`,
  tutorial, CHANGELOG; OCR expanded + Wikipedia link; AGENTS.md
  docs-build command.
- Docs build verified: `make html` succeeds after installing
  `requirements-docs.txt` (sphinx 9.1 + sphinxcontrib-typer).

## Errors and Lessons

- chromadb hardcodes the DB filename; offer folder paths only.
- pypdfium2 `get_metadata_dict()` drops custom Info keys; scan `Subject`
  for an embedded DOI/URL instead.
- Docling CPU conversion is the bottleneck (~127 s/PDF with `--no-ocr`,
  pre-existing); the biblio tiers add milliseconds.
- The cache-hit regex fallback used to degrade a good first-pass template
  -- fixed by persisting `(docs, extracted)`; also removed a stale leftover
  block that overwrote the restored extraction.
- "Full-body regex" is really "first 3000 chars of the front matter".
- Test after each logical bit; pytest must run from inside the package dir.
