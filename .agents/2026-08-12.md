## Lessons

- A corrupt pack can hold both unreachable-corrupt AND good reachable objects;
  before deleting it, confirm nothing reachable lives only in it (or just
  fetch-recover from origin instead).
- Large-file churn can trigger an interrupted auto-gc that corrupts a pack.

## Update (night): evaluator loop + fallback design

- `retrieval_attempts` redefined as the total number of retrieval passes (the
  initial query retrieval, `retrieve_more_info` k-increases, and `modify_query`
  re-retrievals). The increment moved from `GenerateRetrievalQuery` to
  `RetrieveInfoNode` (runs once per pass); `max_retrieval_attempts` default
  bumped 2 -> 5 as a combined budget.
- Exhausted-budget routing now splits on context quality: insufficient context
  (coverage < 0.3 or confidence < 0.3) -> training-data fallback or
  clarification (per `fallback_to_training_data`); ungrounded or empty answer
  -> clarification; otherwise -> `best_effort`, delivering the generated
  grounded answer with a hardcoded warning (`AnswerUser.BEST_EFFORT_WARNING`).
  Ungrounded answers already route to rewrite via the evaluator earlier; at
  exhaustion it means rewriting was not worth it.
- Router simplified; an explicit `rewrite_answer` directive is guarded so the
  retrieval branch cannot swallow it.
- Fallback and best-effort warnings render as GitHub-style alerts
  (`> [!WARNING]`) in the NiceGUI bubbles via the markdown2 `alerts` extra
  + a small CSS callout.
- Docs: `docs/concepts/rag.rst` now explains the per-source score scales
  (vector store = cosine in `[0, 1]`, BM25 = raw unbounded keyword score)
  and that they are informational context, not a comparable ranking
  (ordering comes from the RRF rank fusion).

## Lessons

- Exhausted-budget handling should split on context quality: low
  coverage/confidence -> training data, ungrounded/empty -> clarify, else
  deliver best-effort with a warning.
