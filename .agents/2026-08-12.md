### PyTorch / CUDA install guidance

Quadro P1000 (Pascal, CC 6.1): CUDA 12.9+/13.x dropped CC < 8.0 kernels,
so torch 2.13.0+cu130 reported the GPU but had no sm_61 kernels; last
compatible build is 2.13.0+cu126, and torchvision must pair from the same
index. Venv fixed with `torch==2.13.0+cu126` + `torchvision==0.28.0+cu126`.
Repo artifacts: root `requirements-torch.txt` (self-documenting), an
"(Optional) PyTorch / CUDA" section in `docs/install.rst`, and
`scripts/test_torch.py` (env snapshot + real CUDA matmul) which catches
the build-vs-kernel mismatch that `collect_env` misses.

### E2E store-creation retest

Docling's auto device detection picked `cuda:0` for the RT-DETR layout
model; every page failed because Triton requires CC >= 7.0 (P1000 is 6.1),
so layout silently fell back (degraded quality, ~11s/page wasted). Fix
(user decision, docs-only): force CPU via env vars `DOCLING_DEVICE=cpu`
+ `DOCLING_NUM_THREADS=16`, documented in the RAG tutorial and concepts
pages. Re-run confirmed: no layout failures, 41 real heading chains, a
clean metadata-map template (full crossref DEFAULT).

`metadata-map*.json` being ingested (and erroring) is correct behaviour --
`.json` is in Docling's `FormatToExtensions`; users keep only source files
in the source dir.

### Text normalization for retrieval

PDF extraction embeds soft hyphens, NBSP and BOM, which split words and
skew BM25/embedding matches. New `klea_utils.stores.utils.normalize_text()`
drops soft hyphens, maps no-break spaces, strips BOM/zero-width/bidi/
variation-selectors, and NFKC-folds ligatures/full-width/superscripts/
typographic spaces; em/en dashes deliberately kept (user decision).

Applied at ingestion (chunk text, heading chains, template `DEFAULT` via
`_normalize_extracted_metadata`) and to the retrieval query (symmetric
index/query normalization); metadata-map heading keys are normalized on
load. DEBUG tracing at all four call sites. Existing `.klea-cache` entries
are stale (keyed by file hash) -- CHANGELOG documents a one-off `--force`
re-run.
