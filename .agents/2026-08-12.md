## Completed

### Rename klea-code -> klea-agent

Package/CLIs/env prefix/graph name renamed (`klea_code` -> `klea_agent`,
`klea-code` -> `klea`, `KLEA_CODE_` -> `KLEA_AGENT_`, data now under
`~/.local/share/klea/`). Details in git + CHANGELOG v0.4.0 (wip).

### PyTorch / CUDA on the Quadro P1000 (CC 6.1)

CUDA 12.9+ dropped CC < 8.0 kernels, so the venv needed torch
`2.13.0+cu126` with a paired torchvision from the same index. Added a
self-documenting `requirements-torch.txt`, an install.rst section, and
`scripts/test_torch.py` (env snapshot + real CUDA matmul) because
`collect_env` misses the build-vs-kernel mismatch.

### E2E store creation

- Docling auto-picks `cuda:0`, but Triton needs CC >= 7.0, so layout
  failed page-by-page and silently degraded. Fixed docs-only (no CLI
  flag): `DOCLING_DEVICE=cpu` + `DOCLING_NUM_THREADS=16`, documented in
  the RAG tutorial/concepts.
- `metadata-map*.json` inside the source dir being ingested is correct
  behaviour (`.json` is a supported Docling format); now only the
  template and the exact `--metadata-map` file are excluded from ingestion.
- `chunk` reminds the user to review the template before `store`, and the
  `chunk`/`store`/`build` paths exit 1 (instead of reporting success) when
  nothing was processed; `write_heading_template` no longer clobbers an
  existing template on an empty run.

### Text normalization for retrieval

`normalize_text()` (strips soft hyphens, NBSP, BOM, zero-width/bidi/
variation selectors; NFKC folds ligatures/fullwidth/superscripts/
typographic spaces; em/en dashes kept) applied at ingestion (chunk text,
heading chains, template DEFAULT) and to the retrieval query. Existing
`.klea-cache` entries are stale -- one-off `--force` re-run (in CHANGELOG).

### Metadata for the answer LLM

- `urls` list expanded to `url_1`/`url_2`...; `url_<label>` keys display as
  `label: <url>` in the references panel; `url_doi` derived from a found
  DOI (doi.org). Template and DOI cache both written with
  `ensure_ascii=False` (literal UTF-8; the ASCII-only rule is code/docs
  only).
- `store` sanitizes chunk metadata for Chroma (drops empty-list/None
  values on copies) because Chroma rejects empty-list metadata; the cache
  and BM25 corpus keep `headings: []` as the "no headings found" marker.
- Full e2e verified: chunk -> template -> store -> retrieval (vector +
  BM25) against the nml-elife fixture.

## Lessons

- Mock third-party objects against their real contract (docling
  `DocMeta.headings` defaults to `None`; Chroma rejects empty-list
  metadata values) or tests miss real bugs.
- A batch run that swallows per-file errors must still fail loudly (exit
  non-zero, no empty template overwrite) -- it is easy to "succeed" with
  nothing done.
- Old GPUs: `DOCLING_DEVICE=cpu`; after a bulk rename, `rg` for both the
  lowercase module token and the PascalCase class token, then re-run `ty`.
