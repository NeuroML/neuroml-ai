# Compulsory metadata map with hierarchical heading folding

## Context and Problem Statement

Klea stores are collections of chunked documents.  Each chunk needs
bibliographic and provenance metadata (file name, heading chain,
authors/title/DOI/URL, per-heading ``url*`` overrides, year) for
citations, reference-material rendering
(``serialize_reference_material`` groups by source file with a one-time
header per file), and filtering (``filter_fields`` per domain).

Early Klea left the metadata map optional: ``store`` could run without
``--metadata-map`` and ingest callers in ``docs/tutorials/create-and-use-rag``
did not pass one; ``chunk`` wrote a generated template but ``store``
did not require it.  ``DEFAULT`` existed but was not compulsory per
file, and heading-chain keys were partially unused (the template was
generated with fully-qualified ``"Chapter > Section"`` chains, but
``store`` only looked up a single heading).  Missing per-file
``DEFAULT`` entries and mismatched heading keys produced silent gaps
in citations and per-heading ``url`` overrides.

Should a metadata map be required, and how should a chunk's heading
chain be resolved against it?

## Decision Drivers

* Citations need at least ``DEFAULT`` per file (authors/title/journal/
  year/DOI or ``"unknown"``-like provenance) -- a file with no entry
  should not be stored silently.
* Heading-specific overrides (e.g. a leaf ``2.1 Neurons`` sets only
  ``url``) must be gap-filled against the file's ``DEFAULT`` so a
  section that only sets a URL still inherits authors/year/journal;
  empty ``{}`` placeholders the researcher did not fill must fall
  through rather than erase ``DEFAULT``.
* The autogenerated template must be consumable: a researcher can fill
  a deep chain, a chapter suffix, or a single heading, and the most
  specific entry wins.
* The map must be validated and its keys normalised
  (``normalize_text`` NFKC) so paste artifacts do not miss.

## Considered Options

* **A. Optional metadata map (old)** -- ``store`` runs without
  ``--metadata-map`` and without a template; missing file entry is
  tolerated (returns ``None``).  Rejected: silent citation gaps; the
  tutorial never surfaced the template gap-fill contract.
* **B. Compulsory per-file ``DEFAULT`` with hierarchical folding
  (chosen)** -- every source file must have a ``DEFAULT`` entry in the
  map.  ``StoresBuilder._resolve_metadata(file_name, headings,
  metadata_map)`` (``ingestion.py:1173``) looks up the file, then
  matches the heading chain from most specific to least specific: the
  full joined chain (``"Chapter > Section"`` as written by
  ``write_heading_template``), then progressively shorter suffixes
  (``"Section"``), then progressively shallower ancestor chains
  (``"Chapter"``).  The first non-empty matching entry is merged over
  ``DEFAULT`` (gap-fill: heading-specific keys win, ``DEFAULT`` fills
  everything else).  An entry that matches but is empty (``{}``) falls
  through to the next candidate, then to ``DEFAULT``.  ``map-lint``
  (``klea_utils/stores/map_lint.py``) and the template writer enforce
  the contract; an empty ``{}`` map is rejected, a missing file key is
  a ``ValueError``, and ``_load_metadata_map`` normalises keys via
  ``normalize_text`` (``ingestion.py:1118``).
* **C. Per-heading compulsory entries** -- require an entry for every
  heading chain.  Rejected: the template writes every heading chain
  already, but forcing the researcher to fill every leaf would make
  the map unusable; gap-fill + ``DEFAULT`` inheritance covers the leaf
  that has no specific metadata.

## Decision Outcome

Chosen option: "B. Compulsory per-file ``DEFAULT`` with hierarchical
folding".

* ``ingestion.py:1081`` ``_load_metadata_map`` loads and validates the
  JSON (dict of ``str`` -> ``dict``), remembers the exact file so
  ``_find_files`` can exclude it from the ingestible set, and
  normalises heading keys.  ``_resolve_metadata_map`` returns ``None``
  when no explicit ``--metadata-map`` and no ``.klea-cache/
  metadata-map.template.json`` exist (``store`` CLI aborts when that
  happens); ``build`` generates a map from what ``chunk`` produced.
  An empty map raises ``ValueError`` even when passed explicitly.
* ``ingestion.py:1173`` ``_resolve_metadata`` per-file folding as
  described above; ``_fold_metadata_map``-adjacent logic keeps
  ``DEFAULT`` inheritance strict.  ``klea_utils/stores/map_lint.py``
  reports the map health (per-file ``DEFAULT`` presence, heading key
  normalisation, empty placeholders) as shown in
  ``docs/developer-info.rst`` and ``docs/troubleshooting.rst``
  (``map-lint``/``store-lint``).
* ``stores/utils.py`` ``normalize_text`` (NFKC + soft-hyphen strip,
  see ``adr/0018-message-memory.md`` ibid) is reused for heading key
  normalisation so ``DEFAULT`` and heading keys are comparable.
* The map shape ``{file_name: {"DEFAULT": {}, "heading-chain": {...}}}``
  is the same that ``write_heading_template`` emits and that
  ``klea-stores-create chunk`` auto-falls back to when no
  ``--metadata-map`` is given (``_resolve_metadata_map`` logs
  ``auto-falling back to .klea-cache/metadata-map.template.json``).
  ``docs/tutorials/create-and-use-rag.rst`` now directs users to copy
  the template out and review it before ``store``.

### Consequences

* Good, because every file has at least ``DEFAULT`` provenance; missing
  entries are caught as a hard error rather than a silent citation gap.
* Good, because heading-chain matching makes the autogenerated template
  consumable: a deep ``"Chapter > Section"`` fill, a suffix, and an
  ancestor are all valid and the most specific wins with ``DEFAULT``
  gap-fill.
* Good, because empty ``{}`` placeholders do not erase ``DEFAULT`` --
  the researcher can template the whole corpus and leave most headings
  empty.
* Bad, because existing stores built without a per-file ``DEFAULT``
  must be regenerated (breaking, but pre-1.0 and the linter makes it
  visible).
* Bad, because forcing a ``DEFAULT`` per file makes the map file
  larger on large corpora; the per-file folding adds a small
  ``O(headings)`` lookup per chunk.

### Confirmation

* ``klea_utils/stores/map_lint.py`` / ``klea_utils/ui/stores_create.py``
  ``map-lint`` command succeeds only when every file has ``DEFAULT``;
  empty map → ``ValueError`` (``ingestion.py:1144``).
* ``utils_pkg/tests/test_stores_map_lint.py`` covers the per-file
  ``DEFAULT`` + gap-fill + normalisation cases.
* ``docs: make html`` still renders the store-create pipeline with the
  template auto-fallback note; ``ty`` extra-paths still resolve
  ``RetrieverConfig`` with ``per-file`` map.

## Pros and Cons of the Options

### Compulsory per-file DEFAULT with hierarchical folding (chosen)

* Good, because ``DEFAULT`` provenance is never missing
* Good, because heading-chain matching makes the template consumable
  with gap-fill
* Bad, because older stores must be regenerated

### Optional metadata map

* Good, because ingest never aborts on missing map
* Bad, because silent citation gaps
